# 投委会与研究室

[English](investment-council.md) · [文档导航](README.md) · [数据与隐私](privacy.zh-CN.md)

在「**智能体搭建**」配置一个小型研究团队，在「**投研讨论室**」讨论标的，并保存每一版结论及其证据。启用投委会后，它也会审查当前模拟策略产生的候选交易。它不会连接券商或执行真实交易。

## 配置团队

每个投委会固定包含三个角色：

| 成员 | 职责 | 默认模型档位 |
|---|---|---|
| 研究员 | 根据已有证据提出投资理由。 | 快速模型 |
| 质疑者 | 独立检查事实缺口、下行风险和等待理由。 | 快速模型 |
| 组合经理 | 汇总前两位的公开观点，形成批准、等待或否决结论。 | 慢速模型 |

你可以修改成员名字、研究偏好，并为每位成员选择快速或慢速档位。档位使用「**API 设置**」中配置的模型，不是为每位成员另选一个供应商。成员共用保存下来的证据快照；研究员和质疑者先独立研究，再交由组合经理汇总。他们不能调用任意工具、改变候选交易的方向或数量，也不能发送订单。

想先免费使用，可以关闭投委会，并将额外 AI 审核指令留空。不配置模型 Key，也能使用基础分析、公共行情和投资者明确设定的价格规则。启用投委会的 Builder 配置需要模型已配置才能激活。未配置模型时进入讨论，会得到明确标注的基础「**等待**」报告，不会出现伪造的 AI 成员发言。供应商的“免费模型”仍可能要求自己的 Key，并受供应商的可用性、限额和收费规则约束。

## 参与讨论并保存结论

1. 保存一个 Builder 配置，再进入「**投研讨论室**」，选择配置和股票代码，创建讨论。
2. 启动研究。成员回复保存后会出现在页面中；页面通过轮询更新，不是逐 Token 流式输出。
3. 留下你的观点或限制条件。每条留言都会提升输入修订号，让旧结论失效。运行中收到留言时，服务会在原任务预算内有限重跑；已结束的讨论则需点击「**继续研究**」。
4. 需要时暂停。已经发送给供应商的请求可能继续完成并产生用量，但暂停状态或过时修订不能成为当前有效审批。
5. 查看各版决策简报、异议、下次复核条件、证据快照和原始研究报告链接。旧版本继续保留。讨论会冻结创建时的配置及版本；修改 Builder 配置后，应新建讨论使用新版本。

每条留言最多 2,000 字符，每个讨论最多 30 条用户留言。自动工作最多尝试三个输入修订版本。继续或暂停不会重置这个讨论的任务预算。模型收到的是带出处的证据短摘录；完整采集快照与用户留言仍保存在实例数据库。较长的用户指令可能触及单次输入上限，此时结果为等待。

内置采集器仍缺少经过核验的财务报表。关键研究证据缺失时，研究型批准会被阻止。对于已经明确配置的价格触发候选，可以按「**仅规则审查**」评估，并披露研究数据缺口；它不代表 AI 对未来价格的预测。格式无效、模型不可用或预算达到上限时，会保存等待或失败记录，不会批准订单。

继续讨论也会复用冻结的证据。需要更新行情和研究数据时，请新建讨论；在旧讨论中要求“再检查一下”不会刷新数据源。

## 研究结论如何影响模拟盘

讨论里的「启动」「继续」「暂停」和留言只影响研究，从不直接下单。手动创建的讨论不附带可执行候选订单。

已启用的 Builder 扫描会先根据配置规则生成确定性的候选交易。启用投委会审核时，服务审查该候选的股票、方向、数量和参考价格。只有匹配这个候选及配置版本的当前审批，才能进入后续模拟下单检查。成交事务会再次核对讨论修订号、审批时效、新行情、价格变化、账户状态，以及风控和交易节奏限制。已经使用的审批不能重复用于其他订单。模拟成交后，获批报告会关联对应订单。

对证据和价格区间相同的等待、否决或不可用结果，服务会复用缓存，避免为同一个想法反复支付否决费用。缓存批准仍要求候选精确匹配、修订号有效。出现新信息也不保证立即自动重跑，还要遵守扫描节奏。任何真实交易都需要你另外到券商手动操作。

## 默认交易节奏

这些配置适用于已激活 Builder 的扫描，包括手动点击运行的扫描。它们与已有的单笔限额、每日笔数、日亏损、现金及持仓检查共同生效。

| 限制 | 默认值 |
|---|---|
| 常规复核间隔 | 5 个工作日 |
| 订单数量 | 滚动 7 天内最多 2 笔 |
| 同一股票冷静期 | 3 个工作日 |
| 换手金额 | 滚动 7 天内最多占当前模拟账户权益的 10% |

复核间隔按各市场本地日期计算。配置、研究或持仓输入变化后，可能提前进入复核，但自动复核会合并为每个配置、每只股票、本地每日最多一次，失败或否决也计入。7 日限制覆盖整个账户，待审批订单也会预占额度。目前“交易日”只排除周六、周日，**不排除交易所节假日**。这是低频模拟器，不是带完整交易日历的执行系统。

## 预算与用量

在智能体搭建或设置页可以打开「**研究预算**」。预算按账号保存，通过共享服务端 LLM 客户端发出的请求会在调用前检查，包括供应商重试和连接测试。同一讨论的所有成员和输入修订共用一个任务标识。

| 设置 | 默认值 |
|---|---:|
| 每个 UTC 日的 Token | 60,000 |
| 每个 UTC 月的 Token | 600,000 |
| 每个任务的 Token | 24,000 |
| 单次输入 Token | 6,000 |
| 单次输出 Token | 1,000 |
| 每个任务的调用次数 | 8 |
| 每个 UTC 日的调用次数 | 30 |

服务端按 UTF-8 字节保守估算输入，并为输入及输出上限预留额度。因此长提示词可能比供应商自己的分词计算更早达到限制。供应商返回可信用量时，以返回值结算；失败或没有用量信息时，保留保守预留值。因此在途和中断任务仍会占用额度。每日、每月周期按 **UTC** 边界重置；任务额度不会随之重置。预算只能阻止后续请求，不能撤回已被供应商接受的调用，也不能控制供应商的账单系统。

可选输入／输出单价由你填写，单位为美元／百万 Token。任一价格未填时，费用显示未知。这里的金额是估算，不是供应商账单，实际收费可能不同。截图识别／OCR 使用另一条调用路径，**不在这套 LLM 预算内**。该功能不承诺免费或无限量 Agent 群聊。

用户可以修改自己的限额。这套账号预算不是服务器共享 API Key 的运营方总费用上限；使用共享 Key 时，各用户的用量可能累加到同一账单，运营方还应在供应商侧设置额度。

## 保存与部署边界

留言、成员偏好、冻结的配置、完整证据快照和报告版本会持久保存在实例数据库。模型供应商收到本次选取的证据摘录、候选和配置上下文、请求中包含的完整用户留言，以及前序成员观点摘录。预算记录保存模型／任务标识、Token 数、状态和时间戳；预算台账本身不保存提示词正文。托管运营者能够访问自己的数据库和服务器密钥，详见[数据与隐私](privacy.zh-CN.md)。

当前支持的部署仍是**单应用实例**。重启会把未完成的讨论标记为暂停，并让旧修订失效，不会自动恢复模型调用。启动恢复目前会暂停数据库里所有运行中的投委会讨论，因此不能将多个同时运行的副本当作持久化任务队列使用。重启后请主动确认是否继续；此前预留或已消耗的任务用量仍然计入。
