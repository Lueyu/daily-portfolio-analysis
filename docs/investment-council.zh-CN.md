# 投委会与研究室

[English](investment-council.md) · [文档导航](README.md) · [数据与隐私](privacy.zh-CN.md)

在「**智能体搭建**」配置一个小型研究团队，在「**投研讨论室**」讨论标的，并保存每一版结论及其证据。启用投委会后，它也会审查当前模拟策略产生的候选交易。它不会连接券商或执行真实交易。

## 配置团队

每个团队可以选择 **2–6 位成员**，其中恰好一位主持人／经理。内置价值、成长、风控、技术、新闻、宏观和主持人七种模板。默认三人团队包含以下角色：

| 成员 | 职责 | 默认模型档位 |
|---|---|---|
| 研究员 | 根据已有证据提出投资理由。 | 快速模型 |
| 质疑者 | 针对研究员的实际论点提出反证和问题。 | 快速模型 |
| 组合经理 | 总结共识、分歧和下一步核验；只有附带明确候选交易时才作审批。 | 慢速模型 |

可以修改名字、角色定位、性格、研究方向、表达风格及补充提示词。每位成员可以选默认模型连接，也可以混搭其他已保存连接及其快速／慢速模型。「**API 设置 → 团队模型连接**」最多保存八个额外的 OpenAI 兼容公共 HTTPS 连接。密钥在服务端加密保存，群聊配置只记录连接引用；连接失效时会停止，不会偷偷换用另一把 Key。

默认三人团队按「研究 → 质疑 → 回应 → 总结」依次发言；更大团队会在回应和总结前增加观点。成员会看到前序发言、用户引导与证据，可以请求有次数限制的财报、估值、新闻、行情或可选联网检索。自定义提示词不能覆盖工具权限、候选交易方向／数量或费用上限。消息可以展开查看**公开分析依据**、问题和出处，不展示模型的私有思维链。

讨论室每次模型请求最多等待两分钟，网络失败不自动重试。超时请求可能已被供应商计费，因此保留预留用量；检查供应商状态后，可手动从保留的发言断点继续。

配置参考了 [CrewAI 的角色／目标／工具划分](https://docs.crewai.com/en/concepts/agents)和 [AutoGen 的发言人选择／终止条件](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html)。本项目自行实现有预算限制的流程，没有引入这两个框架。角色、性格和提示词决定观点及研究方法；研究方向决定关注资料；简洁／详细／追问风格影响表达。工具权限、终止条件和公共预算不交给角色提示词控制。

想先免费使用，可以关闭投委会，并将额外 AI 审核指令留空。不配置模型 Key，也能使用基础分析、公共行情和投资者明确设定的价格规则。启用投委会的 Builder 配置需要模型已配置才能激活。未配置模型时进入讨论，会得到明确标注的基础「**等待**」报告，不会出现伪造的 AI 成员发言。供应商的“免费模型”仍可能要求自己的 Key，并受供应商的可用性、限额和收费规则约束。

## 参与讨论并保存结论

1. 进入「**投研讨论室**」，输入股票代码，选一个团队预设并定制成员，再在聊天里补充问题。Builder 配置可选；独立研究室不会激活策略。
2. 创建后自动开始一轮研究。中间是成员聊天，底部输入框保持可用；完整回复保存后通过轮询更新，不是逐 Token 流式输出。
3. 随时补充观点。已完成一轮后发送消息，会带上上一轮结论自动继续一轮；研究中发言会在原任务预算内引导讨论。Enter 发送，Shift+Enter 换行，中文输入法选字不会误发送。暂停或失败的讨论需要手动继续。
4. 需要时暂停。已经发送给供应商的请求可能继续完成并产生用量，但暂停状态或过时修订不能成为当前有效审批。
5. 右侧报告栏按版本整理结论；手机上点击报告按钮打开。点开一版查看结论、异议、证据与关联报告或模拟订单。讨论会冻结创建时的配置及版本；修改 Builder 配置后，应新建讨论使用新版本。

每条留言最多 2,000 字符，每个讨论最多 30 条用户留言。每次完成的发言和下一位发言人都持久保存，中断后从断点继续，不重跑整轮。继续或暂停不重置累计任务预算。模型收到有长度限制的上下文，完整来源与留言保存在实例数据库。独立研究报告以积极、中性或谨慎观点总结，不产生交易批准。通过成员面板新建讨论，可以使用修改后的团队。

配置 Finnhub Key 后，受支持的美股可采集估值指标、近期公司新闻和财报原始科目，并保留报告期、披露日期与 SEC 出处。接口权限和数据完整性取决于供应商；连接测试成功不代表所有科目都有数据。负债科目缺失、报告过旧、市场不支持、权限或网络错误会分别说明，已有事实继续保留。关键研究证据缺失时，研究型批准仍会被阻止；明确配置的价格触发候选可按「**仅规则审查**」评估并披露缺口，不代表 AI 对未来价格的预测。

美股财报不完整时，自动尝试免费的 SEC EDGAR 备用来源，并核对申报编号、币种和报告期。「**联网检索**」默认关闭，打开后使用已保存的 DeepSeek 连接。搜索按供应商规则单独计费：每个任务最多两次、每个 UTC 日最多二十次。网页摘录用于补充讨论，不能充当已核实财报或绕过交易审核。详见[研究数据与工具](research-data.md)。

新一轮研究获取当前资料，中断后继续则保留原有断点与证据。每份报告保存其发布时的数据快照。组合估值或汇率失败不会阻断个股研究，但暂不能提供组合仓位建议。任务额度、每日额度、供应商限流与账户余额分别处理。

## 研究结论如何影响模拟盘

讨论里的「启动」「继续」「暂停」和留言只影响研究，从不直接下单。手动创建的讨论不附带可执行候选订单。

已启用的 Builder 扫描会先根据配置规则生成确定性的候选交易。启用投委会审核时，服务审查该候选的股票、方向、数量和参考价格。只有匹配这个候选及配置版本的当前审批，才能进入后续模拟下单检查。成交事务会再次核对讨论修订号、审批时效、新行情、价格变化、账户状态，以及风控和交易节奏限制。已经使用的审批不能重复用于其他订单。模拟成交后，获批报告会关联对应订单。

对证据和价格区间相同的等待、否决或不可用结果，服务会复用缓存，避免为同一个想法反复支付否决费用。缓存批准仍要求候选精确匹配、修订号有效。出现新信息也不保证立即自动重跑，还要遵守扫描节奏。任何真实交易都需要你另外到券商手动操作。

## 默认交易节奏

这些配置适用于已激活 Builder 的扫描，包括手动点击运行的扫描。它们与已有的单笔限额、每日笔数、日亏损、现金及持仓检查共同生效。

| 限制 | 默认值 |
|---|---|
| 常规复核间隔 | 5 个工作日 |
| 订单数量 | 滚动 7 天内最多 2 笔 |
| 同一股票冷静期 | 3 个工作日 |
| 换手金额 | 滚动 7 天内最多占当前模拟账户权益的 10% |

复核间隔按各市场本地日期计算。配置、研究或持仓输入变化后，可能提前进入复核，但自动复核会合并为每个配置、每只股票、本地每日最多一次，失败或否决也计入。7 日限制覆盖整个账户，待审批订单也会预占额度。目前“交易日”只排除周六、周日，**不排除交易所节假日**。这是低频模拟器，不是带完整交易日历的执行系统。

## 预算与用量

在智能体搭建或设置页可以打开「**研究预算**」。预算按账号保存，通过共享服务端 LLM 客户端发出的请求会在调用前检查，包括供应商重试和连接测试。同一讨论的所有成员和输入修订共用一个任务标识。

| 设置 | 默认值 |
|---|---:|
| 每个 UTC 日的 Token | 60,000 |
| 每个 UTC 月的 Token | 600,000 |
| 每个任务的 Token | 24,000 |
| 单次输入 Token | 6,000 |
| 单次输出 Token | 1,000 |
| 每个任务的调用次数 | 8 |
| 每个 UTC 日的调用次数 | 30 |

服务端按 UTF-8 字节保守估算输入，并为输入及输出上限预留额度。因此长提示词可能比供应商自己的分词计算更早达到限制。供应商返回可信用量时，以返回值结算；失败或没有用量信息时，保留保守预留值。因此在途和中断任务仍会占用额度。每日、每月周期按 **UTC** 边界重置；任务额度不会随之重置。预算只能阻止后续请求，不能撤回已被供应商接受的调用，也不能控制供应商的账单系统。

可选输入／输出单价由你填写，单位为美元／百万 Token。任一价格未填时，费用显示未知。这里的金额是估算，不是供应商账单，实际收费可能不同。截图识别／OCR 使用另一条调用路径，**不在这套 LLM 预算内**。该功能不承诺免费或无限量 Agent 群聊。

用户可以修改自己的限额。这套账号预算不是服务器共享 API Key 的运营方总费用上限；使用共享 Key 时，各用户的用量可能累加到同一账单，运营方还应在供应商侧设置额度。

## 保存与部署边界

留言、成员偏好、冻结的配置、证据快照和报告版本持久保存在实例数据库。各所选模型供应商收到限定长度的证据、候选和配置上下文、用户留言与前序发言。可选 DeepSeek Search 收到股票代码和研究查询。预算记录保存模型／任务标识、用量、状态和时间戳，不保存提示词正文。托管运营者能够访问自己的数据库和服务器密钥，详见[数据与隐私](privacy.zh-CN.md)。

当前支持的部署仍是**单应用实例**。重启会把未完成的讨论标记为暂停，并让旧修订失效，不会自动恢复模型调用。启动恢复目前会暂停数据库里所有运行中的投委会讨论，因此不能将多个同时运行的副本当作持久化任务队列使用。重启后请主动确认是否继续；此前预留或已消耗的任务用量仍然计入。
